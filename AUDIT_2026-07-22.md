# VIGIL Audit Report — 2026-07-22

## Executive Summary

VIGIL v0.5.5 builds clean (`go vet` + `go build` pass), 6/6 eBPF probes attach successfully on kernel 7.0.0-28-generic. The previous audit's 12 CRITICAL bugs (eBPF link leaks, PID reuse, path traversal, network isolator no-op, unbounded maps, etc.) are ALL FIXED. However, VIGIL has **5 remaining issues** causing runtime failures and false positives.

---

## Issues Found

### ISSUE-1: CRITICAL — Dashboard blocked for 10 minutes during baseline learning

**File:** `cmd/vigil/main.go:88-93`

**Problem:** `base.Learn()` is a BLOCKING call. The dashboard (`dash.Start()`) is called AFTER baseline learning completes. With `learn_duration = "10m"` in `/etc/vigil/vigil.toml`, VIGIL has **no dashboard, no detection, no alerting for 10 full minutes after startup**. The service appears dead.

**Fix:** Move `dash.Start()` BEFORE `base.Learn()`, or run baseline learning in a goroutine so the dashboard starts immediately.

### ISSUE-2: HIGH — Systemd service doesn't pass config file

**File:** `/etc/systemd/system/vigil.service`

**Problem:** `ExecStart=/usr/local/bin/vigil` — no `-config` flag. VIGIL starts with defaults (2min baseline, no auth token, no dashboard_addr override). The config at `/etc/vigil/vigil.toml` (10min baseline, auth token set) is never loaded.

**Fix:** `ExecStart=/usr/local/bin/vigil -config /etc/vigil/vigil.toml`

### ISSUE-3: MEDIUM — Missing browser/sandbox process exclusions cause false positives

**File:** `internal/syscallarg/syscallarg.go`

**Problem:** Old alert log shows repeated false positives from:
- `snap-update-ns` (CAP_SYS_ADMIN)
- `glxtest` (CAP_SYS_ADMIN) 
- `vaapitest` (CAP_SYS_ADMIN)
- `forkserver` (CAP_SYS_ADMIN)
- `Sandbox Forked` (CAP_SYS_ADMIN)
- `localsearch-ext` (CAP_SYS_ADMIN)

These are all legitimate Firefox/GNOME sandbox processes. `snap-confine` is excluded but the others are not.

**Fix:** Add these comm names to the ExcludeComms lists in the cap-sys-admin and cap-net-admin rules.

### ISSUE-4: MEDIUM — `firefox` unshare triggers container escape alerts

**File:** `internal/containerguard/containerguard.go`

**Problem:** Firefox uses `CLONE_NEWPID` (pid namespace) for content isolation — this is legitimate sandboxing, not container escape. The `isLegitContainerProcess()` list doesn't include `firefox`.

**Fix:** Add `firefox` to the `legit` list in `isLegitContainerProcess()`. Also add `gnome-shell` which may use unshare for session isolation.

### ISSUE-5: LOW — Config file has `learn_duration = "10m"` which is too long

**File:** `/etc/vigil/vigil.toml`

**Problem:** 10-minute baseline learning is excessive for a desktop system. Combined with ISSUE-1, this means VIGIL is non-functional for 10 minutes after every restart. The default (2min) is more reasonable.

**Fix:** Reduce to 2-3 minutes, and fix ISSUE-1 so the dashboard starts during learning.
